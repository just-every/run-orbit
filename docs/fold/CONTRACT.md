# Orbit fold generation 1

This application generation extends the accepted native Orbit edition at
`1cc919c0d9b7a30e02e39dca7f2351286fc4c72a` through the real expansion parent
`85f8295a5e22c3ab7f018e7f20fe21e548b2e912`. It is a distinct application
contract. The original CONTRACT.md and artifact-v1 contract, tests, fixtures,
limits and resource envelope remain unchanged and mandatory for their native
behavior. This declaration adds no infrastructure binding: the Worker, one D1,
assets and minute timer remain the same owned resources.

- Native operators remain equal full operators in exactly one workspace. The
  collaborator class is explicit, invited, accepted, restricted and never promoted
  by ordinary provisioning, removal, reinvitation or restore. Roles and record or
  field grants apply only to that class. Current native sessions, membership,
  policy epochs, row visibility, field grants and expiry fence reads and commits.
- Reports calculate complete authorized native CRM populations. They disclose
  filters, grouping, time window, missing values, zero denominators and empty
  populations. Saving requires the exact reviewed inputs. Reopen and export
  recheck current source revisions, epochs and authority before disclosure.
- Fixed text contact forms compile a specific D1 HTML artifact and form revision.
  Native full approval binds their hashes. Publication persists its operation and
  receipt. Public GET serves those exact bytes. Public POST atomically stores a
  native contact when needed, submission, one signal and signal timeline, and
  optional exact consent wording. Replays cannot duplicate those effects or
  overwrite an existing contact. Publication, quota, source and privacy fences
  apply in the same transaction. Capture grants no outreach authority.
- Transfer generation 3 is explicitly `orbit-fold-1`. It retains the base
  100-table allowance and 20 named selected feature tables. A complete
  native v2 legacy import can preserve its exact baseline plus only its known
  missing native additions (0013: privacy contexts and mail conflicts; 0014:
  mail conflicts). Its durable receipt binds the unchanged v2 manifest, every
  ordered part digest and count, every source table and column, and the exact
  owner schema inventory and hash, including views and their INSTEAD OF
  triggers. The target must have the same installed schema; an archive does not
  execute owner DDL. Re-export and restore carry structural
  evidence; they do not claim external issuer authentication. A caller label
  grants no capacity. Extra owner tables, changed owner schemas, absent source
  tables or widened additions invalidate that receipt. The absolute transport
  envelope is 122, while fresh current profiles remain at 120, without
  increasing the actual D1 100-physical-column limit. Typed aliases use internal
  hidden rowid, and binary values use the versioned codec. Ordinary cells retain
  native v2 scalar validation (safe integer INT, numeric REAL, string TEXT). Only
  an explicitly encoded BLOB may carry SQLite binary storage through an affinity
  column; escaped marker text still follows the ordinary scalar rules. Native v2 input uses
  complete known source generations; missing arbitrary tables are corruption.
  Credentials, sessions, invitations, grants and capture authority do not travel.
  Domain intent and evidence survive, while restored collaborators and public
  publication require new authorization. Privacy matching contexts precede
  anonymous suppression proofs and contacts. Complete-job reservations remain
  held until actual cleanup, including rollback copies, is proved.

Forecasts, FX, goals, experiments, campaign engines, workflow builders/runtimes,
account graphs, uploads, broad schema/workspace administration and Base auth
migration remain outside this generation. The canonical identity is
`just-every/orbit`; its public source repository is `just-every/run-orbit`.
This contract is source intent, not runtime, hosted, provider or release acceptance.

The complete-capacity transfer profile targets paid D1's 10 GB database limit.
Free D1 has a 500 MB platform limit; the shipped binding does not select or
automatically detect a billing tier, and the reservation cannot enlarge that
limit. Source-specific planning includes serialized parts, typed snapshots and
stages, rollback coverage, index keys, page fill, WAL allowance and 64 MiB batch
headroom. One shared reservation is acquired atomically before transfer storage
is created and retained through cleanup. Existing unfinished v2 jobs must be
finished and discarded before a new reserved fold transfer can begin. Every archive write atomically checks
the reservation, planned growth and schema generation. Supported D1 `size_after`
metadata is observed before and after batches and retained as high-water evidence;
it is not an in-transaction physical-size SQL fence. Ordinary non-archive writes
can grow between observations; the platform ceiling remains the final physical
boundary. Missing metadata fails the operation. Local D1 qualification does not
prove the hosted platform's quota enforcement.

D1 metadata and platform limits: [return object](https://developers.cloudflare.com/d1/worker-api/return-object/)
and [limits](https://developers.cloudflare.com/d1/platform/limits/).

Migration 0016 first refuses any unfinished pre-fold import through the existing
transactional runtime-control guard, before fold DDL or data writes. The installed
native edition must finish or abort that import before the ordinary migration
retry. A legacy stage is never silently interpreted as a fold stage or dropped.

New exports persist their aliased snapshot layout. Unmarked native v2 snapshots
retain their original column names through advance, download and discard after
upgrade. A format number alone never determines the stored snapshot layout.

Import creation reconciles a lost acknowledgement only against an exact durable
job owned by the same native actor. Repeating the same manifest recovers that
job; it does not repeat staging. A failed post-commit observation remains a
visible failure with the transfer ID. The native Records screen can discover
unfinished restores for the current actor and resume or cancel them, while the
unchanged CLI can retry the same archive or resume by its transfer ID.

Failed export observations likewise expose a retained snapshot for the current
native actor to discover, resume or discard; a new request never silently reuses
an older snapshot. After a restore durably finishes and revokes its destination
actor, any current full native operator may retry only the exact terminal job's
cleanup before starting the next reserved transfer. Each cleanup mutation checks
current full native class and the stored terminal job, progress and generation
catalog in the same transaction. Restored collaborators cannot invoke this path,
and no old operator or session is recreated to release storage.

If a view changes during restore, forward writes stop. Explicit rollback restores
only the locally captured target view and INSTEAD OF trigger definitions, in one
transaction with the exact job/progress/generation/catalog-hash and current full
native authority checks. Base tables, indexes and table triggers must remain
unchanged. View triggers are dropped before views, and views are recreated before
their triggers, using safely quoted identifiers. The final and every later
rollback fence requires the original complete schema. Archive input never
provides executable DDL. A changed durable target catalog fails its stored hash
before any DDL. Platform-owned sqlite_ and _cf_ views are outside owner recovery.

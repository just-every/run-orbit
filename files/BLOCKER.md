# SURFACE-005 completed-success replay boundary

The selected brief requires every later source sync call to compute gated after a provider token answer requires a person.

A public MCP probe performed an accepted sync, caused native Capture to retain an actual Google invalid_grant token answer, and replayed the earlier successful sync using its original arguments and idempotency key. The current response still reported standard and returned its original successful receipt. The provider received no new request. The same observation also occurred under held policy: the old success retained standard and review, while fresh attempts and the refused operation's replay computed gated and approval.

The edition classifier does compute gated from the current source state. The Base pipeline then selects the completed operation's original classes over those current classes: ./src/base/modules/agent-door/pipeline.ts lines 133–153 and 185–186. Its cached mutation branch returns the saved receipt without running the edition action, at lines 208–236. This is Base's retained-effect receipt contract, not a missing native Capture connection or a credential problem.

No Base runtime or pin was changed by this task. The required current gated decision and person-only handoff for a historical successful replay need a supported Base replay contract change. Clearing call custody, disabling idempotency, replacing the policy chokepoint or inventing a second native execution would violate existing requirements.

The native adapter, provider refusal persistence, fresh gated calls, refused-call replay, current authority, counts-only output and native reconnect progress are preserved on the named cloud branch. Full SURFACE-005 remains unclaimed. All existing provider account and consent holds remain unchanged. This is a real Base dependency for the strict every-later-call guarantee; no READY is claimed for the partial branch.
